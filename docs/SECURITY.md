# SECURITY — NeuroOS App Factory

## 1. Принципы

- **NO FAKE SUCCESS:** безопасность не декларируется — проверяется сканерами и тестами.
- Секреты никогда не попадают в код, логи и тело запросов.

## 2. Работа с ключами

- AI-ключи передаются только как **key_ref** (ссылка на хранилище секретов);
  сам ключ не включается в тело запросов и логи (покрыто тестом гигиены ключей).
- Провайдер включается только после успешного smoke-test (`ProviderRegistry.enable`).
- `.env` / `.env.*` в `.gitignore`; секретных файлов в git нет (проверено).

## 3. RUNNER (исполнение команд)

- Белый список команд: git, node, npm, pnpm, npx, cargo, rustc, tsc, vitest.
- Таймаут с SIGKILL; маскирование секретов в выводе; хвост лога 8 KB; SHA-256 логов.
- Покрыто 7 тестами.

## 4. Целостность артефактов

- POST артефакта требует SHA-256; расхождение объявленного и вычисленного → 409.
- Контрольные суммы релизов: `releases/v0.1.0/checksums-sha256.txt`.

## 5. Ворота как контроль доступа решений

- G0 и G6 — **owner-only** (попытка одобрения другим → GateApprovalError, 409).
- RELEASED-переход запрещён без утверждённого G6 и всех критериев DONE
  (REST и sync; 409).
- Каналы релизов: stable требует G5+G6, beta — G5 (409 со списком missing).

## 6. Сканирование (в CI, каждый push)

- **Сканер секретов** (`scripts/security-scan.mjs secrets`): приватные ключи,
  ghp_/github_pat_, AWS AKIA, xox*, Bearer-секреты, секреты в env-присваиваниях.
  Блокирующий. Self-test пройден. Текущее состояние: 0 находок.
- **SAST** (`scripts/security-scan.mjs sast`): eval, new Function,
  dangerouslySetInnerHTML, innerHTML, exec с интерполяцией, shell:true — только
  по кодовым файлам. Блокирующий. Текущее состояние: 0 находок.
- **Аудит зависимостей** (`pnpm audit --prod`): continue-on-error (виден в логе).
  Найденные ранее 2 moderate (react-router) устранены обновлением до 7.18.0.
- TypeScript strict во всех пакетах; typecheck 0 ошибок.

## 7. Сеть и данные

- Hardening API: `bodyLimit` 2 МиБ (413 при превышении); заголовки
  `x-content-type-options: nosniff`, `x-frame-options: DENY`,
  `referrer-policy: no-referrer` на всех ответах.

- Сервер по умолчанию слушает 127.0.0.1:3000 (loopback).
- Персистентность — атомарная запись (tmp+rename); повреждённый снапшот не
  приводит к падению (старт с чистым состоянием).
- Офлайн-очередь хранит операции в localStorage браузера; секреты туда не пишутся.

## 8. Честные ограничения

- Аутентификация/роли пользователей API — DONE (API v0.7.0): токены из
  `NF_AUTH_TOKENS` (`token:role`), роли owner/engineer/viewer, Fastify onRequest-hook
  (401 без валидного токена; viewer — только GET; engineer — рабочие операции без
  ворот/релизов/настроек; owner — всё). `/healthz` и пути вне `/api/v1/` открыты;
  без токенов — честный открытый режим (`auth: "disabled"`). Покрыто 7 тестами
  (`apps/server/src/auth.test.ts`). WebSocket `/ws` при включённой аутентификации
  требует токен (`/ws?token=...` или Authorization на upgrade); без токена — 401
  на upgrade. Хранение токенов в переменной среды —
  промежуточное решение; интеграция с секретным хранилищем отложена. Токен в
  веб-интерфейсе хранится в localStorage браузера (задаётся в Settings); при
  HTTPS-развёртывании это приемлемо, без HTTPS — только для доверенной сети.
- DAST, промышленные SAST (Semgrep/CodeQL) — NOT IMPLEMENTED (собственный
  паттерн-сканер как промежуточное решение).
- Подпись артефактов — NOT IMPLEMENTED (нужны сертификаты владельца).
- HTTPS/обратный прокси — вне скоупа репозитория (инфраструктура развёртывания);
  без него Bearer-токены передаются в открытом виде.
