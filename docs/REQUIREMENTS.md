# REQUIREMENTS — NEUROOS APP FACTORY

Версия: 0.1.0 · Статус: DRAFT → на утверждение (GATE 0)
Источники: «Промпт 1» (master development prompt, STAGE 0), «003 промпт» (STANDARD —
UNIVERSAL MULTIPLATFORM APP BUILDER). Приоритеты: M — must, S — should, C — could.

## 1. Функциональные требования

### 1.1. Управление идеями и спецификациями

- **RF-1 (M)** IDEA STUDIO: приём идеи в свободной форме и по шаблону §15 стандарта
  (название, назначение, аудитория, функции, доп. возможности, режим работы, платформы,
  дизайн, ограничения); сохранение как `idea_brief.raw_text` + `structured`.
- **RF-2 (M)** IDEA STUDIO: анализ идеи — уточняющие вопросы, риски, полнота данных.
- **RF-3 (M)** SPECIFICATION ENGINE: генерация полного технического задания и критериев
  приёмки (`project.acceptance_criteria`) из идеи; редактирование и версионирование ТЗ.
- **RF-4 (M)** AI ARCHITECT: генерация архитектуры, стека, структуры проекта, стратегии
  платформ, плана Offline/Online, плана сборки и тестирования (STAGE 0 продукта).

### 1.2. Разработка

- **RF-5 (M)** CODE BUILDER: управление исходным кодом проекта (Git-репозиторий на проект),
  поэтапная реализация STAGE 1–4, проверка сборки/тестов после каждого значимого изменения.
- **RF-6 (M)** UI STUDIO: дизайн-система, экраны, навигация, адаптивность; учёт особенностей
  каждой платформы; светлая и тёмная темы.
- **RF-7 (M)** Запрещено: фейковые данные вместо работающей функциональности без явного
  запроса демонстрационного режима; заглушки, выдаваемые за реализацию.

### 1.3. Тестирование и аудит

- **RF-8 (M)** TEST CENTER: автоматизированные функциональные и интеграционные тесты;
  проверка сохранности данных при перезапуске, offline-режима, синхронизации.
- **RF-9 (M)** AUDIT CENTER: независимая проверка качества, ведение AUDIT.md по каждому
  значимому этапу (что проверялось, команды, результаты, файлы, пройденные/непройденные
  тесты, ограничения, невыполненные критерии, подтверждённый статус).

### 1.4. Сборка, релиз, обновления

- **RF-10 (M)** BUILD CENTER: сборка артефактов по матрице — EXE/MSI, APP/DMG/PKG,
  AppImage/DEB/RPM, APK/AAB, IPA/проект подписанной сборки, Web, PWA; каталог `/releases/`.
- **RF-11 (M)** Запрещено заявлять о готовом установочном файле, если он фактически не
  собран и не проверен; недоступные форматы помечаются BLOCKED с причиной.
- **RF-12 (M)** RELEASE HUB: версии, релизные заметки, каналы распространения, статусы
  RELEASE_CANDIDATE → RELEASED только при выполненных критериях приёмки.
- **RF-13 (S)** UPDATE MANAGER: проверка и доставка обновлений произведённых продуктов;
  корректное удаление стандартными средствами ОС.

### 1.5. Платформенность произведённых продуктов

- **RF-14 (M)** Каждый проект по умолчанию целится в: Web, PWA, Windows 10/11 x64, macOS
  (Apple Silicon/Intel), Linux (основные дистрибутивы), Android (смартфоны/планшеты),
  iOS (iPhone/iPad) — с поэтапной реализацией и проверкой каждой платформы.
- **RF-15 (M)** Произведённые продукты поддерживают Offline (локальная БД, очередь
  отложенных операций, восстановление после перезапуска) и Online (синхронизация,
  разрешение конфликтов, защита от дублирования операций, целостность данных).

### 1.6. ИИ-слой

- **RF-16 (M)** AI PROVIDER HUB: подключение разных моделей/провайдеров, управление
  API-ключами, настройки, назначение модели на задачу, история выполнения, обработка
  ошибок и лимитов; замена провайдера без переписывания бизнес-логики.
- **RF-17 (M)** Запрещено заявлять о наличии API/интеграций без технической проверки
  документации и доступов.

### 1.7. Реестр и управление

- **RF-18 (M)** ARTIFACT REGISTRY: на проект — исходный код, ТЗ, архитектурные документы,
  диаграммы, тестовые сценарии, результаты аудитов, журналы сборки, установочные файлы,
  контрольные суммы, релизные заметки, документация; версионирование, целостность,
  разграничение доступа, восстановление.
- **RF-19 (M)** PROJECT MANAGER: список проектов, статусы жизненного цикла, дашборды
  (Global, Projects, Workspace, AI, Build, Audit, Release, Settings).

## 2. Нефункциональные требования

- **RN-1 (M)** NO FAKE SUCCESS: запрет имитации выполнения, непрогнанных тестов, скрытия
  ошибок, подмены БД демонстрационными объектами, выдачи прототипа за приложение.
- **RN-2 (M)** Управляемые переходы жизненного цикла: в RELEASED только при выполненных
  обязательных критериях; запрет автоматического утверждения критических этапов только
  на основании ответа ИИ.
- **RN-3 (M)** Безопасность: изоляция проектов, безопасное выполнение команд, контроль
  прав, управление секретами (никаких ключей в коде/репозитории), аудит действий,
  защита репозиториев, контроль зависимостей, ограничение доступа ИИ-агентов к файловой
  системе, резервное копирование.
- **RN-4 (M)** Воспроизводимость: Git, автоматизированное тестирование, CI/CD, проверки
  качества и безопасности, автоматизированная сборка, контроль зависимостей.
- **RN-5 (S)** Единый дизайн-система уровня Apple × Linear × Enterprise SaaS: тёмный
  графит #111827, бирюза #18D6D1, синий #0A6CFF, целадон #A4D9BB, розовый #F86E8F,
  тёмный teal #033438; умеренный glassmorphism; минималистичная навигация.
- **RN-6 (S)** Интерфейс удобен для управления большим количеством продуктов.
- **RN-7 (M)** Отчёт по каждому этапу в формате §14 стандарта (8 разделов, честные статусы).

## 3. Ограничения и допущения

- Исполнительская среда — агент в изолированной песочнице; сборка под macOS/iOS и под
  Windows выполняется на соответствующих ОС (в песочнице Linux) — соответствующие сборки
  на STAGE 7 получают статус BLOCKED, пока нет доступа к целевым ОС.
- NeuroOS Core (React + Vite, Tauri 2, ADR-F-002/003) — референс стека; репозиторий Core
  владельцем не передан (см. AUDIT.md, п. «Ограничения»).
- Публикация в сторах, подписи, нотаризация — зона ответственности владельца.

## 4. Критерии приёмки STAGE 0 (вынесены в QUALITY_GATES.md, GATE 0)

1. Все 13 документов STAGE 0 существуют и отражают фактический анализ, а не заглушки.
2. Требования покрывают все пункты §3–§9 «Промпт 1» и §1–§9 стандарта.
3. Каждое требование трассируемо к модулю и к Gate.
4. Ограничения среды зафиксированы честно (статусы BLOCKED, а не «сделано»).
