# ARTIFACT_REGISTRY — NEUROOS APP FACTORY

Версия: 0.1.0 · Статус: PROPOSED → на утверждение (GATE 1)

## 1. Назначение

Каждый проект имеет собственный реестр артефактов. Реестр — источник истины о том, что
фактически существует: «результат подтверждается проверяемым артефактом» (NO FAKE SUCCESS).

## 2. Состав (на проект)

| Класс артефакта | Примеры |
|---|---|
| source_ref | ссылка на git-репозиторий/коммит/тег проекта |
| spec | ТЗ (версии), ответы IDEA STUDIO |
| architecture | architecture_doc, диаграммы, ADR |
| test_report | отчёты TEST CENTER (команды, результаты) |
| audit_report | заключения AUDIT CENTER, AUDIT.md проекта |
| build_log | журналы Runner по сборкам |
| installer | EXE, MSI, APP, DMG, PKG, AppImage, DEB, RPM, APK, AAB, IPA, web-бандл, PWA-пакет |
| checksum | SHA-256 для каждого installer |
| release_notes | заметки релиза по версиям |
| documentation | README, ARCHITECTURE, TECHNICAL_SPECIFICATION, INSTALLATION, BUILD, SECURITY, TEST_REPORT, RELEASE_NOTES |

## 3. Хранение и структура

- **Метаданные** — PostgreSQL (таблица `artifact`, DATA_MODEL.md §1).
- **Содержимое** — S3-compatible storage: ключ вида
  `{project_id}/{kind}/{version}/{filename}`.
- **Каталог `/releases/`** — проекция реестра: готовые к распространению версии по
  платформам (формируется RELEASE HUB только из артефактов с совпавшей контрольной суммой).
- **Исходники** — в Git (per-project repo); в реестре — ссылки (commit SHA, tag), а не копии.

## 4. Версионирование

- Версии продукта — semver; каждый артефакт привязан к версии проекта.
- Документы (ТЗ, архитектура) версионируются; предыдущие версии не перезаписываются.
- Сборки неизменяемы: перезапись артефакта той же версии запрещена — только новая версия.

## 5. Целостность

- SHA-256 вычисляется при регистрации и проверяется при каждом чтении/выдаче.
- Расхождение суммы — инцидент целостности: артефакт помечается недействительным,
  событие — в `audit_log`, Gate, ссылающийся на артефакт, подлежит перепроверке.
- Резервное копирование S3-хранилища и БД по расписанию; восстановление тестируется
  (восстановление без теста считается невыполненным).

## 6. Доступ

- Разграничение по ролям: owner (всё), engineer (рабочие артефакты), viewer (чтение).
- Установочные файлы и release notes публичны только через каналы RELEASE HUB.
- Все операции записи — через API реестра; прямая запись в S3 из модулей запрещена.

## 7. Регистрация (единая процедура)

```
register(project, kind, platform?, version, content) →
  1. вычислить SHA-256 и размер
  2. положить объект в S3 по ключу
  3. создать запись artifact
  4. вернуть artifact_id (его и ссылают Gates)
```

Артефакт, не прошедший регистрацию, не существует для конвейера.
