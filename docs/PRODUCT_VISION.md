# PRODUCT_VISION — NEUROOS APP FACTORY

Версия: 0.1.0 · Статус: DRAFT → на утверждение (GATE 0)

## 1. Проблема

Создание полноценного кроссплатформенного продукта сегодня требует команды из 6–9
специалистов и связывает воедино разрозненные инструменты: редакторы кода, генераторы ТЗ,
CI, системы сборки, магазины приложений. Идея до пригодного к распространению продукта
проходит длинный путь, на котором теряются качество, воспроизводимость и контроль.

## 2. Решение

NEUROOS APP FACTORY — единая производственная платформа: пользователь формулирует идею,
фабрика проводит её через управляемый конвейер

```
IDEA → SPECIFICATION → ARCHITECTURE → DEVELOPMENT → TESTING → AUDIT → BUILD → RELEASE → UPDATE
```

с обязательными контрольными точками (Quality Gates), реестром артефактов и мультипровайдерным
ИИ-слоем. Результат — не сайт и не прототип, а полноценное приложение: Web, PWA, Windows,
macOS, Linux, Android, iOS — с локальной работой offline, онлайн-синхронизацией,
установочными пакетами, обновлениями и документацией.

## 3. Для кого

- Владельцы продуктов и предприниматели — довести идею до устанавливаемого продукта.
- Небольшие команды и интеграторы — стандартизованный конвейер вместо ручного зоопарка инструментов.
- Экосистема NeuroOS — фабрика производит приложения, совместимые с NeuroOS Core (React + Vite, Tauri 2).

## 4. Ключевые ценности продукта

1. **Один продукт — все платформы.** Единая кодовая база, адаптированные интерфейсы,
   несколько платформ распространения; без дублирования бизнес-логики.
2. **Offline-first + Online.** Каждый произведённый продукт обязан работать локально без
   интернета и синхронизироваться онлайн без потери данных.
3. **Доказуемое качество.** Gate-модель: продукт не может быть выпущен, пока обязательные
   критерии приёмки не переведены в DONE с подтверждающими артефактами.
4. **Независимость от ИИ-провайдера.** Абстрактный AI Provider Layer: замена модели или
   провайдера не требует переписывания бизнес-логики.
5. **Полная трассируемость.** Каждая версия проекта хранит ТЗ, архитектуру, тесты, аудиты,
   сборки, контрольные суммы и релизные заметки в Artifact Registry.

## 5. Принципиальные отличия

| Не является | Является |
|---|---|
| Генератором HTML-страниц / сайтов | Производственной системой полного цикла |
| Панелью управления с кнопками «в никуда» | Конвейером, где каждый элемент выполняет функцию |
| Привязкой к одному ИИ | Мультипровайдерной платформой с маршрутизацией задач |
| «Чёрным ящиком» без доказательств | Системой артефактов и контрольных точек |

## 6. Пользовательские сценарии (top-3)

1. **Идея → продукт.** Пользователь вводит идею (шаблон §15 стандарта), фабрика строит ТЗ
   (SPEC ENGINE), архитектуру (AI ARCHITECT), согласовывает по GATE 0/1, затем реализует,
   тестирует, собирает и публикует версии.
2. **Производство по стандарту.** Для каждого продукта исполняется нормативный стандарт
   «Universal Multiplatform App Builder» (STAGE 0–8) с отчётностью по каждому этапу.
3. **Сопровождение.** UPDATE MANAGER доводит обновления до установленных копий; RELEASE HUB
   ведёт версии и каналы распространения; Artifact Registry обеспечивает откат.

## 7. Метрики успеха (проверяемые)

- Проект, прошедший конвейер, имеет собранные и проверенные артефакты минимум для Web и
  одной нативной платформы; остальные форматы — с честным статусом и причиной.
- 100 % релизов проходят GATE 5/6 (сборки проверены, релиз утверждён).
- Замена ИИ-провайдера выполняется без изменений кода модулей фабрики (только конфигурация).
- Ни один релиз не содержит пунктов приёмки со статусами, отличными от DONE, без явного
  решения владельца.

## 8. Ограничения видения

- Публикация в App Store / Google Play, подписи и нотаризация требуют учётных записей и
  сертификатов владельца — фабрика готовит пакеты и инструкции, но не владеет доступами.
- Сборка под iOS/macOS требует оборудования Apple; без него статусы сборок — BLOCKED,
  а не «готово».
- Фактическая доступность форматов (EXE, DMG, APK, …) фиксируется в плане сборки проекта
  после выбора его стека.
